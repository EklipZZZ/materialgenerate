# 测试与验收

## 自动化命令

```bash
pnpm api:generate
pnpm api:check
pnpm test
pnpm ts-check
pnpm lint
pnpm build
```

正常开发流程中只需要运行 `pnpm test`，它会先检查 `docs/openapi.json` 是否与共享 schema 和 API route 清单一致，再运行单元测试。

## API 合约检查

`api:check` 检查：

（1）OpenAPI JSON 是否存在且内容为当前生成结果；

（2）OpenAPI 版本是否为 3.1.0；

（3）`src/app/api/**/route.ts` 中导出的 HTTP 方法是否全部被记录；

（4）是否存在文档中有、代码中没有的路由；

（5）认证、SSE、材料类型和敏感字段说明是否仍在生成结果中。

## 业务场景验收

### 申请人

（1）个人独立开发：著作权人使用 `person`，填写身份证字段；

（2）企业/单位独立开发：著作权人使用 `organization`，填写单位类别和统一社会信用代码；

（3）多个个人合作开发：可以录入多个自然人，并要求合作开发协议；

（4）企业与个人混合：同一申请同时录入 `person` 和 `organization`；

（5）旧数据：只有 `company_name`/`credit_code` 的申请可读取、编辑和生成；

（6）服务端：委托开发和下达任务开发值可被识别，首版 UI 不开放。

### 申请表字段和 AI 补全

（1）企业/单位著作权人不显示园区或成立日期；自然人可以填写出生日期；

（2）申请人、地址、联系人和联系方式全部留空时仍可保存草稿；

（3）环境、编程语言、开发目的、面向领域行业和软件分类超过 50 字符时，前后端均拒绝；

（4）软件技术特点超过 100 字符时，前后端均拒绝；

（5）软件的主要功能可以在草稿阶段暂空或暂时少于 500 字符；超过 1300 字符时不能保存，启动材料生成前必须满足 500～1300 字符；

（6）软件分类、面向领域/行业和编程语言都支持同时勾选多个常用值，并能在独立输入框补充自定义内容；保存后再次打开仍能正确回显；

（7）默认 AI 补全不会填充申请人、联系人、证件、权利和日期，也不会覆盖已有技术字段；用户明确点击“AI 补全并生成主要功能”时，会使用当前页面草稿重写主要功能，返回内容必须为 500～1300 字符，否则重试或返回 422，短内容不得写入；

（8）源码反馈能够读取压缩包、统计源码行数、返回带依据的建议，并且只有勾选后才写回表单草稿。

### 材料包

（1）成功生成源代码 DOCX/PDF；

（2）成功生成用户手册 DOCX/PDF；

（3）成功生成申请摘要 PDF；

（4）合作开发协议可上传、替换和删除；

（5）非合作开发不会把合作协议标记为必需；

（6）签章页初始显示等待官方系统生成；

（7）上传签章页 PDF 后变为已上传；

（8）超过大小限制、扩展名错误或不匹配的材料类型会被拒绝。

### 任务和配置

（1）保存 API Key 后刷新页面和重新登录仍可读取配置元数据；

（2）前端响应和服务端日志不出现完整 API Key；

（3）同一申请同时发起两个生成请求时，一个请求得到冲突响应；

（4）任务失败后可以重新生成；

（5）SSE 中断后，可以通过任务接口读取已经持久化的状态和事件；

（6）生成记录、材料记录和任务记录可以通过关联 ID 对应。

### PDF

（1）中文字体成功加载；

（2）PDF 非空且可以复制文本；

（3）多页文档页码连续；

（4）软件名称和版本号与申请数据一致；

（5）长源代码和长用户手册不会被截断；

（6）PDF 预检能够报告字体、页数、行数或内容一致性提醒。

## Supabase 隔离验收

准备两个已验证邮箱的测试用户：

（1）用户 A 创建申请、材料、生成任务和 LLM 配置；

（2）用户 B 使用自己的 Bearer Token 查询相同 UUID；

（3）用户 B 应得到不存在或无权限结果，不能读取 A 的申请、下载链接、任务、事件或配置；

（4）Storage 中的对象必须保持私有，只能由当前用户通过服务端获得短期链接。

数据库 migration 修改后，应检查所有新增公开表都启用了 RLS，policy 的 `USING` 和 `WITH CHECK` 与 `user_id` 规则一致。

## 部署验收

（1）依次执行 `supabase/migrations/` 中的 migration；

（2）确认 `generated-documents` 是私有 Bucket；

（3）配置 Supabase、转换服务、LLM 加密根密钥和超时环境变量；

（4）执行 `pnpm test`、`pnpm ts-check`、`pnpm lint` 和 `pnpm build`；

（5）在 Vercel 环境完成注册、登录、申请保存、源码上传、生成、材料上传和历史下载；

（6）检查日志不包含 API Key、完整提示词或上游错误正文。
